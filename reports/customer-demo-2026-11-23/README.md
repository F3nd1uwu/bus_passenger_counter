# Проверка готовности демонстрации, 23 ноября 2026

Основной пользовательский сценарий готов для контролируемой демонстрации:
войти, загрузить MP4, дождаться автоматического подсчёта, открыть результат записи
и скачать CSV. Точность распознавания в эту проверку не входит.

## Проверенная установка

Использована минимальная серверная поставка из коммита
`24cbb35c8a9b07ed1d22e915ff84f80c6edaa20a`, отдельный Compose-проект,
собственная PostgreSQL и новые тома. Рабочая БД и арендованный сервер не изменялись.
Установщик `python -m tools.start_portal` собирает образы, запускает базу,
создаёт роль чтения, применяет миграции, предлагает создать администратора
и запускает веб-кабинет с диспетчером. Повторный запуск сохраняет конфигурацию
и существующие аккаунты.

При чистой установке выявлена и исправлена ошибка монтирования загрузок внутрь
каталога исходных видео, доступного только для чтения. Теперь используется
отдельный `/app/uploads`. Исправление включено в обе опубликованные ветки.

## Что выполнено через настоящий браузер

Администратор создал тестовый автобус и загрузил короткий MP4 с читаемыми часами.
Диспетчер самостоятельно построил карту времени и запустил рабочие модели.
Кабинет показывал прогресс, затем «Завершено»: один вход и ноль выходов.
Проверены карточка записи, скачивание её CSV, фильтры дневного отчёта
по дате из видео, формирование и скачивание дневного CSV. Значения скачанных
файлов сопоставлены с PostgreSQL.

Сотрудник с доступом только к этому автобусу вошёл в отдельный аккаунт:

- административные разделы и другой автобус отсутствуют;
- запись администратора отсутствует в списке, прямой адрес её карточки закрыт;
- собственная загрузка автоматически завершилась, результат и CSV доступны;
- повторная загрузка того же исходника с тем же автобусом, камерой и настройками
  не увеличила дневной итог PostgreSQL: остался один вход и ноль выходов.

На узком экране 390 × 844 проверены открытие бокового меню, переход к записям
и форма загрузки. Горизонтального переполнения страницы не обнаружено.

## Автоматические проверки

- 58 тестов веб-кабинета: права, загрузки, очередь, карточки и CSV — пройдены.
- Общий набор: 241 тест, 12 предусмотренных пропусков — без ошибок.
- Дополнительный тест с настоящей PostgreSQL: переход суток, восстановление
  и повтор завершённой записи — пройден. Итог файла не сбрасывается в полночь.
- Проверены миграции, Compose-конфигурации, контрольные суммы моделей
  и состав минимальной поставки. Приватные видео, пароли и служебные БД
  в публикацию не входят.
- GitHub CI для проверенного кода:
  [diploma](https://github.com/F3nd1uwu/bus_passenger_counter/actions/runs/45058989908),
  [server](https://github.com/F3nd1uwu/bus_passenger_counter/actions/runs/45058989578).

Ранее выполненные проверки восстановления очереди, нечитаемых часов,
блокировок и ограничений ресурсов описаны в
[протоколе очереди](../../docs/ARCHIVE_QUEUE.md).

## Что требуется перед передачей заказчику

Владелец обновляет арендованный сервер по инструкции, проверяет запуск службы,
создаёт автобус и личный аккаунт сотрудника. Для доступа без SSH-туннеля нужны
домен, DNS, доступные порты 80/443 и HTTPS-конфигурация. Достаточно того же сервера.
[Пошаговый сценарий](../../docs/CUSTOMER_DEMO.md).

Для первого показа следует взять короткий фрагмент с текущим ракурсом камеры
и читаемыми экранными часами. Нечитаемые или неоднозначные часы переводят
задание в «Требуется проверка». Совместимость с произвольными камерами,
скорость суточного архива и большой парк камер здесь не подтверждаются.
Автоматический обмен с 1С не реализован; CSV пока проверочный.
Надёжность часового узнавания, фильтра персонала и приблизительного определения
детей требует отдельной оценки качества.
