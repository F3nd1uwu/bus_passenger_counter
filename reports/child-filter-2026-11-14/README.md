# Экспериментальное исключение маленьких детей, 14 ноября 2026

**Результат: механизм реализован, полезность для текущей камеры не подтверждена.**
На шести реальных видеофрагментах сохранились все прежние итоги — 30 учтённых
проходов, но **исключений с причиной `CHILD` было ноль**. Это не означает правильное
распознавание взрослых: модель в основном не смогла сделать вывод о возрасте.
Режим оставлен отключённым по умолчанию. Веса детекции людей, жилетки и ReID,
а также текущий профиль `test2` этим экспериментом не заменялись.

## Условия

Пользователь просил примерно отличать маленьких детей от взрослых, ориентируясь
на возраст до семи лет; при сомнении учитывать. Подтверждённые возраста неизвестны.
Рост и размер бокса как самостоятельный возрастной фильтр не применялись.

Использованы TinyCLIP для сопоставления внешнего вида и MiVOLOv2 для дополнительной
оценки по телу. Лица на записи в основном не видны; лицевая модель не включалась.
Нужны три последовательных согласованных результата по разным фрагментам
одного трека. Неопределённый результат сбрасывает подтверждение, старший возраст
запрещает возрастное исключение на текущем треке. Эти правила сознательно снижают
число исключений, чтобы соответствовать условию «при сомнении учитывать».

Это готовые внешние модели без дообучения на возрастах местных пассажиров.
Подробности поведения и запуска — в [инструкции](../../docs/CHILD_FILTER.md).
Параметры сохранены в [profile.json](profile.json), результаты, SHA-256 моделей
и видео — в [results.json](results.json). Исходное видео, лица, crop-изображения
и признаки ReID не публикуются.

## Реальные видеопрогоны

Полный конвейер YOLO + OSNet + жилетка + возрастной worker + подсчёт.
Кадры нумеруются с нуля, обе границы включены. Каждый эпизод начинался с пустой
тестовой памяти; PostgreSQL и рабочая SQLite не использовались.

- **P01, 256000–256800:** прежние 3 IN / 11 OUT → 3 / 11;
  13,59 FPS; 65 оценок возраста, все неопределённые.
- **P02, 262000–263200:** прежние 7 IN / 0 OUT → 7 / 0;
  12,69 FPS; 69 оценок: 67 неопределённых, две «старший возраст».
- **P04, 356000–357400:** прежние 1 IN / 3 OUT → 1 / 3;
  18,32 FPS; 22 неопределённые оценки.
- **P06, 302200–303100:** прежние 3 IN / 0 OUT → 3 / 0;
  14,95 FPS; 35 оценок: 32 неопределённых, три «старший возраст».
- **P07, 306800–307500:** прежние 1 IN / 1 OUT → 1 / 1;
  17,68 FPS; шесть неопределённых оценок.
- **V04, 282100–282950:** прежние 0 IN / 0 OUT → 0 / 0;
  15,52 FPS; десять неопределённых оценок.

Итого: 207 завершённых оценок, 202 неопределённых, пять «старший возраст»,
ноль положительных детских оценок; ошибок worker и незавершённых заданий не было.
Возрастные оценки — отдельные задания по кадрам, а не число уникальных людей.

Все эти участки уже использовались в предыдущих проверках и настройке камеры.
Сохранение прежних счётчиков проверяет отсутствие обнаруженного изменения поведения,
но не является независимой оценкой точности. Пассажир, визуально похожий на мальчика
в P02, продолжает учитываться; исключение маленького ребёнка на этом эпизоде
**не достигнуто**, а его настоящий возраст неизвестен. Прежние пропуски проходов
детектора и трекера данным фильтром также не исправляются.

## Проверка на внешних изображениях

На семи специально выбранных фрагментах CountPeople классификатор дал два
одиночных результата `child`, четыре `adult` и один `unknown`. Выборка взята из
обучающей части внешнего набора, без подтверждённых возрастов, после просмотра
примеров: считать её независимым тестом или вычислять по ней точность нельзя.

Дополнительно рассмотрены три короткие последовательности редких кадров:
ребёнок на руках, ребёнок в красном и ребёнок в зелёном. Ни одна не дала трёх
последовательных положительных результатов. Эти последовательности не заменяют
проверку полного видео, но показывают низкое покрытие при данном правиле.
Два одиночных положительных результата не доказывают способность надёжно исключать
детей в рабочем видеопотоке. Точность и полнота детского фильтра не измерены.

## Скорость и отказоустойчивость

Ryzen 7 5700U, CPU, основной конвейер — четыре потока ONNX; возрастной worker —
один последовательный исполнитель с ограниченной очередью. Асинхронность
не устраняет конкуренцию за CPU. На P02 предыдущий прогон без возрастного фильтра
показал 15,41 FPS, текущий с фильтром — 12,69 FPS. Оба сохраняли видео с боксами;
это отдельные запуски, поэтому разницу нельзя считать контролируемым бенчмарком.
Оснований обещать прежнюю скорость нет.

Добавлены проверки переноса подтверждений при короткой потере ID, отказа от
запоздавшего результата при смене внешности, ограниченной очереди, обработки ошибок,
сброса после перемотки, задержки решения и восстановления после контрольной точки.
Исправлено сохранение нескольких отложенных событий разных треков с общей часовой
личностью: старое событие больше не теряется при сохранении нового трека.

Проверки: `unittest discover` с `RUN_TEST2_REGRESSION=1` и
`RUN_CACHED_VIDEO_REGRESSION=1` — **164 теста, 153 прошли, 11 пропущены, ошибок нет**.
Пропущенные проверки включают отдельные интеграционные окружения и явные флаги
реального видео; шесть описанных выше видеопрогонов выполнены отдельно.

Сжатие хранения констант возрастной модели в FP16 проверено на 34 фрагментах:
максимальное отличие от исходного FP32 составило 0,05956 предсказанного года.
Это проверка численной близости экспорта, а не точности определения возраста.

## Источники и воспроизведение

- [TinyCLIP, проект авторов](https://github.com/microsoft/Cream/tree/main/TinyCLIP)
  и [фиксированный ONNX-экспорт](https://huggingface.co/onnx-community/TinyCLIP-ViT-8M-16-Text-3M-YFCC15M-ONNX/tree/9463a9c508a344c837ffefe9d724f3827bf2dc79).
- [MiVOLO, проект авторов](https://github.com/WildChlamydia/MiVOLO)
  и [фиксированный сторонний age-only ONNX](https://huggingface.co/Sam-Apostel/mivolo-v2-age-onnx/tree/8eb4cd8f5dd4bd28df2c9a43b24bc54d6d139d36).
- [Исторический официальный LICENSE MiVOLOv2](https://huggingface.co/iitolstykh/mivolo_v2/blob/57d119f0fe72a6831dbc28c53c7b1b06873a469a/LICENSE),
  зафиксированный отдельно от ONNX. Не переносите эти условия на текущие ревизии
  или другие веса без проверки их происхождения.

Экспортер `python -m tools.prepare_child_model` скачивает только фиксированные
исходные веса, проверяет хеши и готовит локальные модели; для самого экспорта
нужен `tokenizers==0.23.3`. Рабочий запуск не требует tokenizer и загрузок из сети.

Пример повторного видеопрогона в новый файл отчёта:

```powershell
.\venv\Scripts\python.exe -m tools.evaluate_clip --source data/test2.mp4 --profile test2 --child-mode model --start 262000 --end 263200 --output .local/child_recheck/P02.json --video
```

Из-за фоновой очереди и нагрузки CPU результаты по доступным возрастным пробам
могут различаться между запусками; гарантии побитового совпадения нет.
Старые кэши детекций не подходят для проверки возрастного фильтра: они не содержат
его исходных наблюдений. Рабочее применение с автоматическим исключением детей
пока не рекомендуется: подтверждённого улучшения на этой камере нет.
