# Расширение test2 и проверка дообучения

Проверки выполнены 21–22 ноября 2026 года. Обучение выполнено 16 ноября.
**Рабочими остаются `person_test2_v2` и `work_vest_v4`.** Новые веса обучены и
экспортированы, но обе модели отклонены для замены: улучшение отдельных кадров
не сохранилось в подсчёте проходов. Настройки сервера, профили, БД, карты часов,
часовое правило и OSNet не менялись.

Полный числовой протокол, хеши, история обучения и результаты проверок:
[results.json](results.json).

## Данные и разметка

Для `test2.mp4` первоначально отобраны 1000 новых кадров. После визуальной проверки
73 неоднозначных кадра исключены: плотные перекрытия и слишком маленькие фрагменты
не превращались в отрицательные примеры. Остались 927 новых кадров и 77 прежних
проверенных кадров — **1004 изображения test2**. Их распределение: train 679,
val 163, test 162. Дополнительно в train сохранены 187 старых обучающих кадров
`test.mp4`, чтобы уменьшить потерю качества на первой записи.

Итого для детектора людей: **866 / 163 / 162 изображения** в train / val / test.
В исходной версии разметки 666 / 107 / 122 бокса. Пустых изображений — 359 / 71 / 85.
Люди в жилетках и дети остаются классом `person`: роль определяется отдельно,
подтверждённых возрастов в этих данных нет.

Кадры извлечены последовательным декодированием MP4. Разделение фиксировалось
до обучения по участкам исходной записи, минимальный зазор между частями —
1000 кадров. Прежние train/val/test сохранены. Кадры первого видео из val/test
в обучение не добавлялись. Аугментации выполнялись только в train во время обучения;
копии с шумами не выдавались за новые независимые наблюдения.

Разметка сделана с предложениями исходного детектора, визуальной проверкой
50 обзорных листов и отдельной проверкой исправлений. Для 177 исходных кадров
сохранены явные изменения предложений. Это разметка с помощью модели, а не
независимый эталон двух разметчиков: принятые исходные предложения особенно
влияют на сравнение геометрии боксов при строгом IoU.

При подробном разборе ошибок найден один неверный эталон: в кадре **265634**
общий прямоугольник закрывал двух людей. Подготовлена отдельная ревизия
`datasets/bus_people_test2_expanded_v3_review2`: теперь в test **123 бокса**.
Изображения, train и val побайтно совпадают с исходным набором. Исходный снимок
обучения и первоначальные метрики сохранены. Для исправленного test использованы
те же замороженные предсказания на изображениях с теми же хешами.

Исходный набор обучения: `datasets/bus_people_test2_expanded_v3`.
Актуальная исправленная разметка: `datasets/bus_people_test2_expanded_v3_review2`.
В каждой папке есть YOLO-метки, JSON с боксами и хешами, план выборки и листы проверки.
Видео, изображения и тренировочные запуски остаются локальными.

Для жилетки проверены **569 новых вырезок**, исключены 22 неоднозначные,
добавлены 547. Вместе с прежними 540 вырезками — **1087**:
train 706 (147 с жилеткой), val 166 (15), test 215 (29).
Все обучающие вырезки чёрно-белые; размечена видимая жилетка, не оранжевый цвет
и не личность водителя. Сохранены старые части v4; участок V04 не добавлен в train,
а область P02, ранее использованная для garment train, исключена из нового heldout.
Минимальный зазор между частями этого набора — 500 кадров.
Папка: `datasets/work_vest_test2_expanded_v5_final`.

## Обучение

Детектор людей `person_test2_expanded_v3`: исходные веса `person_test2_v2.pt`,
12 эпох, лучшая по записанному mAP50–95 — 9-я, AdamW, lr 0.00012,
freeze 10, batch 4, 640 px, seed 161126, CPU 3 потока.
Время запуска обучения — 3450.79 с. Применялись умеренные изменения яркости,
масштаба и положения; геометрия rect, mosaic отключён. Вход и архитектура
производственного детектора не увеличены.

Жилетка `work_vest_test2_expanded_v5`: исходные веса v4, 10 эпох,
лучшая — 10-я, AdamW, lr 0.0001, freeze 10, batch 8, 320 px,
seed 42, CPU 2 потока. Время запуска обучения — 1552.81 с.

Обе модели сохранены отдельными ONNX FP32-кандидатами в `models/candidates/`.
Параметры обучения, снимки данных, логи и `.pt` находятся в соответствующих
папках `runs/`. Веса не включены в рабочие профили и не публикуются как проверенный
серверный комплект. ReID не дообучалась: разметка боксов не содержит достаточных
последовательностей с подтверждёнными личностями для такого обучения.

## Отдельные кадры

Одинаковый confidence детектора — 0.30, сопоставление боксов один к одному при
IoU ≥ 0.50. Это метрики обнаружений, **не точность пассажиропотока**.

На исправленном test второго видео (162 кадра, 123 человека в боксах):

- Рабочий детектор: TP 106, FP 6, FN 17; precision 94.64%, recall 86.18%, F1 90.21%.
- Дообученный: TP 110, FP 10, FN 13; precision 91.67%, recall 89.43%, F1 90.53%.

Он обнаружил больше людей, но также создал больше лишних боксов. На val test2
полнота осталась 96/107, FP выросли с 5 до 7. На прежнем val первого видео
результат ухудшился с TP/FP/FN = 61/10/3 до 47/17/17; на test первого видео —
с 83/20/28 до 81/20/30. Сохранение прежних примеров не гарантировало отсутствие
регрессии.

Проверены также три щадящих варианта усреднения исходных и обученных параметров
(доля новых весов 0.10, 0.25, 0.50). Критерий заранее ограничивал рост FP и FN
на обеих val-выборках; ни один вариант его не прошёл. По test доля весов не выбиралась.

Для жилетки использован производственный `VestClassifier`, прежний порог 0.20
и серый вход. На test из 215 вырезок, включая 29 положительных:

- v4: TP 14, FP 1, FN 15, TN 185.
- v5: TP 17, FP 1, FN 12, TN 185.

На val v4: TP 4, FP 0, FN 11, TN 151; v5: TP 4, FP 1, FN 11, TN 150.
Выигрыш полноты на test не компенсирует новый ложный отсев пассажира на val.
Простым повышением порога не удалось сохранить прежние TP и FP одновременно
на val, поэтому новый порог не выбран.

## Подсчёт на видео и ID

Выполнены свежие прогоны Windows / ONNX, кадры не пропускались, время взято
из карт часов камеры. Новые результаты сравниваются с рабочими весами в той же
среде, а не подставляются вместо прежнего Linux/OpenVINO-отчёта.

Рабочая связка прошла **7/8** контрольных эпизодов, новая — **6/8**:

- P02, ожидаемые 10 IN: рабочая связка 7, новая 6. Ухудшение относительно
  рабочего результата, исходная проблема не устранена.
- `control_boardings`, ожидаемые 6 IN: обе связки дали 6.
- V01, V03 и V05: обе связки исключили водителя, события имеют причину `STAFF`.
- N01, ожидаемые 2 IN: рабочая дала 2, новая 1 и ложный `STAFF`.
- N06, ожидаемый 1 IN: обе связки дали 1.
- N10, ожидаемые 1 IN / 1 OUT: обе связки дали 1 / 1.

Отдельно v5 проверена со старым детектором людей: **5/6** garment-контролей.
Три прохода водителя исключены, N01 и N10 сохранены, но в N06 обычный пассажир
ошибочно получил `STAFF`: 0 IN вместо 1. Проблема не решается сохранением только
старого детектора людей.
Для N06 дополнительно повторён исходный вариант с тем же одним CPU-потоком,
что у проверки v5: v4 сохранила 1 IN без `STAFF`. Разница не объясняется только
числом потоков.

На P02 сделаны дополнительные полные трассы с одинаковым одним CPU-потоком.
Все **5 существующих размеченных пар** правильно сопоставлены у обеих версий,
без неразрешённых пар в этих конкретных прогонах. Создано 28 / 31 кратких треков
и 31 / 37 записей галереи соответственно. Эти количества сами по себе не являются
метрикой фрагментации: эталонные ID размечены только для пяти пар.

Например, около кадра 262666 в новом прогоне вошедший человек сопоставлен
с треком, уже имеющим состояние `cabin`; переход не сформирован. Для вывода,
правильно ли выбрана личность, нужна плотная временная разметка этого человека.
Пять удачных пар не доказывают устранение слияний, смен ID или правильность
повторного узнавания через час. Пороги и часовые правила ради числа 10 не менялись.

## Решение и ограничения

Оба кандидата **не приняты для эксплуатации**. Это результат выполненного
обучения и проверки, а не незавершённый запуск. Сохраняется прежний результат
программы; модель с большим числом картинок не включается автоматически.

Следующий полезный материал для обучения и проверки — короткие последовательности
с ID каждого человека и событиями прохода, особенно перекрытия, исчезновение бокса
и возвращение. Также нужны целевые отрицательные примеры одежды, на которой
в полном конвейере возникает ложный `STAFF`. Новые контрольные эпизоды следует
зафиксировать отдельно до следующего подбора параметров.

Разделение здесь идёт по участкам одной записи. Та же камера и тот же водитель
есть в разных частях; часть сцен ранее использовалась для настройки. Эти данные
не подтверждают качество на другом автобусе, независимом рабочем дне или 1700
записях. 7/8 и 6/8 — доля совпавших контрольных эпизодов, не общий процент точности.
Наиболее неоднозначные исключённые кадры не покрыты этой кадровой оценкой.

Эта работа не была оптимизацией скорости: использована та же архитектура.
Проверки точности выполнялись параллельно, их FPS нельзя сравнивать как
производительность моделей. Новые веса не проверялись на арендованном OpenVINO-сервере.

## Воспроизведение

Локальные подробные отчёты, предсказания и трассы:
`.local/test2-expansion-20261116/`. Обзорные листы с людьми в Git не включаются.

Проверка разметки:

```powershell
python -m tools.prepare_archive_dataset verify --dataset datasets/bus_people_test2_expanded_v3
python -m tools.prepare_archive_dataset verify --dataset datasets/bus_people_test2_expanded_v3_review2
```

Для кадровой оценки используются `tools.evaluate_detection_dataset` и
`tools.evaluate_garment_dataset`; новый JSON-результат нужно записывать под
отдельным именем. Для полного конвейера `tools.benchmark_cpu controls`
принимает отдельные `--model` и `--vest-model`, не меняя профиль.
Код выхода 1 при несовпадении с контрольным числом означает провал проверки
качества; подробный JSON при этом сохраняется.

Прошёл 21 сфокусированный автоматический тест подготовки, сопоставления боксов,
garment-разметки, пар ID и передачи кандидатных весов в проверку. Дополнительно
проверены целостность обеих ревизий данных, экспорт моделей и неизменность
рабочих весов. Это не заявление о повторном полном прогоне тестов БД или сервера.
