# Архитектура и правила

## Обработка кадра

1. `core/video_source.py` определяет файл, сетевой поток или USB-камеру, читает кадр
   и назначает временную метку. Для файла используется время записи + PTS, для потока —
   монотонные часы, привязанные к UTC при запуске. После переподключения отмечается разрыв.
2. `core/detector.py` запускает YOLO с классом `person`, проверяет пригодность модели,
   извлекает признаки OSNet и передаёт боксы трекеру.
3. `core/person_detections.py` проверяет часть совпадающих частичных/полных боксов;
   `core/appearance_tracker.py` сопоставляет наблюдения по геометрии и внешнему виду.
   Это эвристики: известные оставшиеся ошибки описаны в [QUALITY.md](QUALITY.md).
4. `core/counter_engine.py` подтверждает происхождение трека в одной зоне и переход
   в другую, присваивает личность, применяет правила повтора и фильтра персонала.
5. `core/service.py` сохраняет состояние и события вместе в локальный SQLite,
   затем доставляет очередь в PostgreSQL. Предпросмотр выполняет те же вычисления
   без открытия рабочих хранилищ.

## Геометрия

Все координаты настроек — доли реального размера кадра. При `ANCHOR_Y=0.5`
точка человека находится в центре бокса. `Y_STREET=0.38`, `Y_CABIN=0.60` задают
две зоны, промежуток между ними поглощает дрожание. `Y_LINE=0.50` — ориентир
визуализации, а не единственная линия принятия решения. `DOOR_X_MIN/MAX`
ограничивают проём по горизонтали.

Нужно минимум `ZONE_CONFIRM_FRAMES=2` последовательных наблюдения в зоне и
`MIN_TRACK_FRAMES=3` наблюдения трека. Первое появление внутри, исчезновение и
неподтверждённый скачок бокса не создают учитываемого прохода. Для другой камеры
границы и `ENTER_FROM` нужно калибровать по исходным кадрам.

В профиле камеры `test2` граница салона уточнена до `Y_CABIN=0.57`.
Исходное значение 0,60 для остальных камер сохранено.

## Личности и час

Трекерный ID — краткая траектория, `identity_id` — попытка сохранить одного человека
после смены ракурса/траектории. У личности хранятся ограниченная галерея признаков,
времена последнего учитываемого IN и OUT и последнего наблюдения. Одновременно
видимые люди не должны разделять одну личность. При неоднозначном ReID создаётся
новая личность, что уменьшает слияния разных людей, но создаёт риск повторного счёта.

Окна IN и OUT независимы. Первый проход каждого направления учитывается; следующий
проход того же направления через время меньше 3600 секунд сохраняется с причиной
`REPEAT_WITHIN_HOUR` и `counted=false`. Исключённый повтор не сдвигает начало окна.
Личности и окна сохраняются при полночном переходе и восстановлении состояния.
Сохранность состояния не доказывает правильность визуального распознавания личности.

Профиль `test2` включает `TRACKER_DRIFT_THRESHOLD=0.6`; по умолчанию защита отключена.
Она сравнивает неуверенный, почти заполняющий кадр бокс с историей примерно
15 наблюдений назад. Разрыв допускается только при недавних подтверждённых
наблюдениях другого перекрывающегося человека. Обычный поворот одного человека
не является достаточной причиной разрыва. История ограничена 21 признаком на трек.
При явном отклонении связи `Detection.separated_from` передаёт старые ID счётчику:
ReID не должен сразу восстановить отвергнутую личность и её исходную зону.
Это локальная эвристика для сливающихся боксов, а не гарантия часового узнавания.

Неопределённые проходы могут ожидать дополнительных признаков. При потере трека
или завершении записи неразрешённый проход попадает в аудит с причиной
`INSUFFICIENT_MODEL_EVIDENCE` без увеличения итогов.

## Персонал

`STAFF_MODE=disabled` — модель жилетки не загружается, персонал учитывается вместе
с пассажирами. `STAFF_MODE=model` требует обученной модели и нескольких уверенных
подтверждений. Поддерживаются классификаторы `staff_vest` / `passenger` и отдельные
детекторы видимой рабочей жилетки. Профиль `test2` использует дообученный v3
на чёрно-белых вырезках и два последовательных подтверждения. Прежнее согласие
двух моделей сохранено для воспроизведения старых проверок; дополнительный
режим пространственного согласия проверяет и совпадение положения жилетки.
Цвет и длительное нахождение возле двери не определяют роль человека.

Негативное решение ожидает дополнительные ракурсы до `STAFF_DECISION_DELAY_SEC`;
подтверждённый персонал исключается сразу. При завершении трека или видео готовые
отложенные события выдаются с исходным временем прохода. Недостаточные признаки
остаются в аудите как `INSUFFICIENT_MODEL_EVIDENCE`. Долгосрочное совпадение ReID
само по себе не переносит признак персонала на новый трек. Веса экспериментальны
и проверены только для одной камеры и жилетки:
[результаты и ограничения](../reports/test2-2026-11-13/REPORT.md).

## Хранение и восстановление

- SQLite атомарно хранит контрольную точку и очередь событий. Два процесса не могут
  пользоваться одним локальным состоянием одновременно.
- PostgreSQL получает события с уникальными UUID. Повторная доставка одного UUID
  не должна повторно увеличивать агрегаты. Запись пакета транзакционная.
- Удалённая контрольная точка не должна опережать доставленные события, её ревизия
  не может регрессировать. Локальное подтверждение удаляет только доставленные события.
- При первом запуске без локального состояния PostgreSQL нужен для проверки удалённой
  контрольной точки. При уже сохранённом состоянии временная недоступность БД допускает
  продолжение с локальной очередью. Ограничение — доступное место на диске.
- Для файла сохраняется следующий кадр, а после восстановления часть предыдущих кадров
  проигрывается для прогрева трекера без повторного учёта. Завершённый файл не считается
  заново при обычном перезапуске.

Ключ совместимости учитывает источник, существенные настройки и содержимое моделей.
Несовместимая конфигурация вызывает явную ошибку. Удаление SQLite для обхода проверки
может потерять очередь/часовую память и привести к повторному счёту. Перенос состояния
нужно делать явно, сохранив резервную копию и проверив подходящий профиль.

## Что означает статистика

`daily_passenger_traffic.total_passengers` — учитываемые IN за дату и автобус;
`total_out` — OUT. `current_day_passenger_traffic` хранит итоги по камерам и датам,
включая прошлые дни. Название таблицы не означает автоматического удаления старых строк.
Для настоящего времени применяется `TIMEZONE`.

Счётчик не оценивает заполненность салона или количество уникальных людей за день.
У нескольких камер свои локальные процессы/идентичности: общая идентификация одного
пассажира между разными дверями этим проектом не реализована.
