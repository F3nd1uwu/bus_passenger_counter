# Разработка, проверки и обучение

## Проверки

```bash
python -m unittest discover -v
python -m tools.check_repository
python -m pip check
```

Обычные тесты проверяют подтверждение переходов, дрожание, повторные IN/OUT,
смену ID, похожих людей, границу часа/полночи, восстановление посреди прохода,
атомарность SQLite, настройку источников, перемотку и реальные экспорты моделей.
Без переменных включения пропускаются PostgreSQL и приватные видео/кеши.

Для **отдельной временной PostgreSQL**, PowerShell:

```powershell
docker run -d --name bpc-test-pg -e POSTGRES_DB=bus_analytics -e POSTGRES_USER=bus_counter -e POSTGRES_PASSWORD=test-local-only -p 127.0.0.1:55432:5432 postgres:16-alpine
# Дождитесь готовности: docker exec bpc-test-pg pg_isready -U bus_counter -d bus_analytics
$env:TEST_DB_PORT = '55432'
python -m unittest discover -v
docker rm -f bpc-test-pg
Remove-Item Env:TEST_DB_PORT
```

Фиксированный пароль здесь относится исключительно к одноразовой тестовой БД.
Тесты проверяют повторную доставку, транзакционный откат, потерянное подтверждение,
восстановление контрольной точки, сетевой сбой и продолжение после остановки службы.
Не направляйте их на рабочую базу.

Для локальных исходных данных можно включить долгие регрессии:

```powershell
$env:RUN_VIDEO_REGRESSION = '1'
$env:RUN_CACHED_VIDEO_REGRESSION = '1'
python -m unittest discover -v
Remove-Item Env:RUN_VIDEO_REGRESSION
Remove-Item Env:RUN_CACHED_VIDEO_REGRESSION
```

Первому режиму нужен `data/test.mp4`, второму — оригинальные `.raw.npz` и признаки
в `data/tracking_improvement_v2`. Эти файлы не публикуются; включённый режим при их
отсутствии завершится ошибкой, а не сделает вид, что регрессия проверена.
При одновременно включённой временной БД и наличии данных выполняется полный набор.

Для проверок текущего `test2` дополнительно установите `RUN_TEST2_REGRESSION=1`.
Ему нужны приватные исходные кеши этой камеры, пути заданы в соответствующих тестах.
Полная текущая проверка публикации описана в [отчёте выпуска](../reports/release-2026-11-14/README.md).

CI проверяет Linux/Python 3.12 с одноразовой PostgreSQL и Windows/Python 3.14.
Пассажирское видео и обучающий датасет CI не получает. Автотесты правил и транзакций
не заменяют ручную оценку качества ML.

Перед публикацией 08.11.2026 на Windows/Python 3.14 прошли **все 85 тестов**, включая
PostgreSQL и приватные видео/кеши. Чистая копия отдельно прошла **81 тест из 85**
на Windows и Linux/Python 3.12 в Docker: четыре приватных проверки ожидаемо пропущены.
Также проверен запуск `test_local.py` с включённым кандидатом на синтетическом видео.
[Протокол проверки публикации](../reports/verification-2026-11-08.json).

Актуальная проверка 14.11.2026: **168/168 без пропусков** с временной PostgreSQL,
`RUN_VIDEO_REGRESSION=1`, `RUN_CACHED_VIDEO_REGRESSION=1` и `RUN_TEST2_REGRESSION=1`.
Она включает новые правила ID, жилетки, экспериментального возраста и поставки.
Исторические 85 тестов выше относятся к предыдущей версии.

## Сравнение с ручными событиями

Для отдельного интервала используйте реальную модель:

```bash
python -m tools.evaluate_clip --source data/test.mp4 --start 465750 --end 467100 --model models/candidates/person_manual_v1.onnx --confidence 0.35 --association-similarity 0.70 --output data/evaluation_A12.json --video
```

Границы нулевые и включённые. Сохраняются JSON со всеми треками/событиями и `.features.npz`;
`--video` добавляет MP4. Вспомогательные скрипты:

- `tools.replay_trace` — повтор правил счётчика на сохранённых траекториях/признаках;
- `tools.replay_detections` — повтор сопровождения на сырых детекциях;
- `tools.compare_detectors` — сравнение боксов по размеченным изображениям.

Эти повторы ускоряют поиск регрессии, но итоговую оценку делайте полным прогоном.
Ручные метки сначала фиксируйте без просмотра прогнозов. Сопоставляйте людей и направления,
а не только итоговые IN/OUT: равные суммы могут скрывать пропуск и лишнее событие.
После настройки на эпизоде он становится известным проверочным сценарием.

`evaluate_clip` задаёт синтетическое начало 2026-11-01 00:00 UTC. Его `detected_at`
не является временем экранных часов записи; для дневной БД используйте `main.py`
с достоверным `VIDEO_START` и корректной временной шкалой источника.

## Ручная разметка и обучение детектора

Видео/датасет находятся локально. Изображения имеют соответствующие текстовые файлы:

```text
images/train/example.jpg  labels/train/example.txt
images/val/example.jpg    labels/val/example.txt
images/test/example.jpg   labels/test/example.txt
```

Одна строка YOLO: `0 x_center y_center width height`, значения нормализованы в 0..1.
Пустой проверенный `.txt` — отрицательный пример; отсутствие `.txt` не считается им.
Разделяйте целые временные эпизоды между train/val/test. Для проверки обобщения нужен
новый день/камера, а не соседний почти одинаковый кадр.

Если сохранён `datasets/bus_people/annotations.json`:

```bash
python -m tools.annotation_review
python -m tools.train_detector --dataset datasets/bus_people --weights models/yolo26n.pt --epochs 30 --device cpu --batch 4 --threads 4 --freeze 10 --patience 8 --name manual_v1
```

Исходный обучающий `.pt` не включён в репозиторий: подготовьте совместимые исходные
веса YOLO26n отдельно. Скрипт проверяет наличие ручных меток и допустимость боксов.
Для экспорта/оценки изучите `python -m tools.export_candidate --help` и
`python -m tools.compare_detectors --help`. Настройку порогов делайте по val;
test не используйте для многократного выбора конфигурации.

Боксы класса `person` обучают детектор, а не часовую память. Для обучения ReID нужны
подтверждённые person_id одного человека в разных ракурсах. Для жилетки нужны
кропы `staff_vest` / `passenger`, включая обычных людей в оранжевой одежде.

## Подготовка экспортов

Готовые необходимые экспорты уже включены и не требуют скачивания при работе.
Для повторного экспорта из доступных исходных весов:

```bash
python -m pip install -r requirements-export.txt
python -m tools.prepare_reid
python -m tools.prepare_cpu_models
```

`prepare_reid` скачивает веса с закреплённой ревизии и проверяет SHA-256.
`prepare_cpu_models` требует исходные `models/yolo26n.pt` и
`models/person_reid.torchscript`; проверяет численную близость ReID для batch 1/2/3.
Не меняйте включённые веса без обновления происхождения/хешей и оценки качества.

## Чистота репозитория

Публикуются код, необходимые модели, документация и числовые отчёты. `.env`,
пароли камеры, SQLite, записи, кадры пассажиров, датасеты, виртуальные окружения,
кеши, архивы экспериментов и папки IDE игнорируются. Приватные данные не нужно
принудительно добавлять через `git add -f` ради прохождения optional-тестов.

`tools.check_repository` проверяет состав Git, контрольные суммы моделей,
согласованность чисел независимого аудита и относительные ссылки в документации.
