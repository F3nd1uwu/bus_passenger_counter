# Проверка ускорения CPU

Экспериментальные инструменты сравнивают движки детектора людей, сохраняя
ReID, жилетку, все кадры и правила подсчёта. Рабочие веса и профиль не меняются.
OpenVINO не входит в обязательные зависимости программы.
В `main.py` и `test_local.py` добавлены явные параметры
`--cpu-detector-backend openvino --detector-cpu-threads 4 --cpu-threads 2`.
По умолчанию используется прежний ONNX Runtime. Смена движка меняет ключ
совместимости checkpoint: для сравнительного прогона используйте отдельные
`STATE_PATH` и тестовые `BUS_ID`/`CAMERA_ID`. Одно изменение числа потоков
не меняет ключ. Веса, временная шкала и правило часа остаются прежними.

## Изолированное окружение

Из полной версии проекта соберите базовый и тестовый образы:

```bash
docker build -t bus-counter:cpu-base .
docker build -f deployment/benchmarks/Dockerfile.cpu --build-arg BASE_IMAGE=bus-counter:cpu-base -t bus-counter:cpu-bench .
mkdir -p .local/cpu-bench
```

Тестовый образ добавляет только `openvino==2026.4.1`. Измерения всех движков
проводите внутри одного образа с одинаковым ограничением CPU. На Linux назначьте
выходному каталогу права записи для UID 10001 контейнера.

## Полный подсчёт на одном участке

Для текущих приватных файлов уже подготовлены карты часов. Пример без записи в БД:

```bash
docker run --rm --cpus 4 --memory 4g --network none \
  -v "$PWD:/workspace:ro" -v "$PWD/.local:/workspace/.local:rw" -w /workspace \
  bus-counter:cpu-bench python -m tools.benchmark_cpu evaluate \
  --source data/test2.mp4 --clock-map data/test2.clock.json \
  --start 262000 --end 263200 --backend onnx --threads 2 \
  --output .local/cpu-bench/P02-onnx.json
```

Повторите с `--backend openvino --detector-threads 4 --threads 2` и другим именем отчёта. Выходы
не перезаписываются. OpenVINO используется только для детектора людей;
предобработка, NMS, ReID, жилетка, трекер и счётчик остаются прежними.
В диагностическом старте Ultralytics сначала напечатает загрузку ONNX;
после callback детектор исполняется выбранным экспериментальным движком.
`--detector-threads` задаёт потоки только детектору; ReID и жилетка используют
`--threads`. Без отдельного значения все модели используют `--threads`.

JSON содержит события и трассу для проверки ID; NPZ — признаки внешности.
Эти файлы приватны и не должны попадать в публичный Git. `--compact` убирает
трассу/признаки; для проверки пар ID его не используйте.

Отдельный `.timing.json` содержит время этапов. Имена с `inclusive` включают
вложенные операции: `identity` входит в `counter`, а `person_predict`, `reid`,
`vest`, `tracker` входят в `detect`. Их нельзя складывать в общий процент.
`pipeline_seconds` включает первый прогрев; `inclusive_wall_seconds` также
включает инициализацию моделей, проверку карты и запись диагностического отчёта.
Режим не измеряет PostgreSQL и не обещает скорость полного рабочего дня.

## INT8 отдельно от рабочих весов

```bash
docker run --rm --cpus 4 --memory 5g --network none \
  -v "$PWD:/workspace:ro" -v "$PWD/.local:/workspace/.local:rw" -w /workspace \
  bus-counter:cpu-bench python -m tools.benchmark_cpu prepare \
  --train-images datasets/bus_people_v2/images/train --samples 128 \
  --output .local/cpu-bench/person-int8.onnx
```

Калибровка выбирает изображения только из указанной папки `train`, с seed 42.
Имена файлов могут содержать имя исходного видео `test`: это не название split.
Брать для калибровки папки `val` или `test` запрещено инструментом. Используется
статическое QDQ-квантование Conv с поканальными весами и уменьшенным диапазоном.
Рядом записываются хеши модели и выбранных изображений. Для оценки добавьте
`--model .local/cpu-bench/person-int8.onnx` к команде `evaluate`.

Результат зависит от процессора и движка; INT8 может работать медленнее FP32.
Подготовка варианта не означает его активацию. Точность калибруется и проверяется
раздельно; известные эпизоды не дают независимой точности за смену.

## Несколько файлов

Создайте приватный JSON-массив заданий с полями `source`, `clock_map`, `start`,
`end`. Для каждого задания создаётся отдельный процесс, трекер и память:

```bash
python -m tools.benchmark_cpu matrix --jobs .local/cpu-bench/jobs.json --workers 1 --threads 2 --output .local/cpu-bench/one-t2.json
python -m tools.benchmark_cpu matrix --jobs .local/cpu-bench/jobs.json --workers 1 --threads 4 --output .local/cpu-bench/one-t4.json
python -m tools.benchmark_cpu matrix --jobs .local/cpu-bench/jobs.json --workers 2 --threads 2 --output .local/cpu-bench/two-t2.json
```

Готовый короткий пример для двух текущих файлов:
`deployment/benchmarks/cpu_jobs.json` (по 250 кадров). Он подходит для проверки
запуска и предварительного сравнения; для выбора сервера повторите на длинных
участках, чтобы затраты инициализации не определяли итог.

Выполняйте эти команды внутри того же тестового контейнера и последовательно.
Сравнивайте `elapsed_seconds` всей партии и `aggregate_fps`, а не FPS одного
работника. Короткие участки чувствительны к загрузке/прогреву моделей.
Ограничение Docker `--cpus 4` задаёт квоту, а не эквивалент четырёх выделенных
ядер сервера. Локальные Ryzen/WSL-результаты нельзя выдавать за замер Intel VPS.

## Сохранение и PostgreSQL

`profile-db` запускает настоящий архивный цикл с временным SQLite, синтетической
галереей 128 личностей и отдельными тестовыми событиями. Он принимает только
явно указанный нестандартный локальный порт PostgreSQL, БД `bus_analytics`,
пользователя `bus_counter` и пароль `test-local-only`.

Используйте исключительно одноразовую локальную тестовую БД. Рабочие `.env`
инструмент не читает. После замера созданные им записи удаляются.

```bash
python -m tools.benchmark_cpu profile-db --source data/test.mp4 --clock-map data/test.clock.json --postgres-port 55442 --start 81271 --frames 600 --identities 128 --threads 2 --output .local/cpu-bench/persistence.json
```

Синтетическая галерея нужна для измерения затрат большой памяти, а не для оценки
узнавания пассажиров. Измеряются также snapshot, локальное сохранение и доставка
в PostgreSQL. Рабочую БД к этому инструменту не подключайте.

Вариант становится кандидатом на внедрение после проверки прежних эпизодов,
жилетки и ID. Самый быстрый результат отдельной нейросети не является критерием
выбора всей системы. Сравнивайте также стоимость обработки полного файла.

## Проверка прежних 25 эпизодов

```bash
python -m tools.benchmark_cpu controls --backend openvino --threads 2 --detector-threads 4 --output .local/cpu-bench/controls.json
```

Этот режим повторно использует загруженные модели, но полностью сбрасывает
трекер и счётчик между эпизодами. Карта каждого источника проверяется по хешу
один раз, затем используется повторно, пока исходник и карта не изменились.
Поэтому его время нельзя сравнивать с запуском отдельного процесса на файл.
Фильтр персонала здесь выключен, как в исходном наборе 25 контрольных итогов.
Для отдельного плана проверки жилетки задайте `--plan` и `--staff-mode model`.
В плане поддерживаются `required_reason`/`forbidden_reason`: нулевой итог без
обнаружения водителя не считается доказательством правильного исключения.
`--shards 2 --shard-index 0` и индекс 1 позволяют разделить проверки на два
независимых процесса; это проверка качества, не сравнительный замер скорости.
