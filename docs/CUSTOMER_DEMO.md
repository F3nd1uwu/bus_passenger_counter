# Демонстрация и самостоятельная проверка

Самый простой вариант для заказчика — готовый адрес кабинета и личный аккаунт.
Устанавливать Python, Docker или подключаться по SSH для загрузки видео не нужно.
Первоначальную установку выполняет владелец сервера один раз.

## Установка владельцем

Нужны Git, Python 3.12 или новее и работающий Docker с Compose. На Windows
используйте Docker Desktop в режиме Linux containers. Для стартового сценария
рекомендуется 4 vCPU и 8 ГБ RAM; свободный диск должен вмещать образы и ваши записи.

В чистом каталоге:

```bash
git clone --single-branch --branch server https://github.com/F3nd1uwu/bus_passenger_counter.git
cd bus_passenger_counter
python -m tools.start_portal
```

В Ubuntu команда Python обычно называется `python3`. Если репозиторий уже
скачан, не клонируйте поверх рабочего каталога: сохраните конфигурацию и обновите
существующую установку по [инструкции обновления](https://github.com/F3nd1uwu/bus_passenger_counter/blob/server/UPDATE.md).

Сценарий создаёт отсутствующие `.env`/`.env.web`, собирает образы, запускает
PostgreSQL, создаёт отдельную роль чтения, применяет миграции, запускает кабинет
и очередь. Старые конфигурации и аккаунты сохраняются. Если администратора ещё
нет, появится стандартный интерактивный запрос логина и пароля. Постоянного
пароля по умолчанию нет. Сборка при первом запуске может занять несколько минут.

Повторный запуск с уже собранными образами:

```bash
python -m tools.start_portal --skip-build
```

Для публичного домена сначала настройте DNS, порты и `WEB_DOMAIN` по
[инструкции HTTPS](WEB.md), затем используйте `python -m tools.start_portal --https`.
Отдельный сервер для сайта не нужен. Доступ по домену не настроится одной покупкой
домена: сертификат выдаётся только после доступности адреса и сервера.

## Как открыть кабинет

На компьютере, где запущен Docker: [http://127.0.0.1:8000](http://127.0.0.1:8000).
Для удалённого сервера удобнее дать заказчику HTTPS-домен. Временный вариант
владельца без домена — SSH-туннель, описанный в инструкции кабинета.

При первом входе администратор:

1. Открывает «Автобусы» и добавляет тестовый автобус с уникальным кодом,
   например `DEMO_BUS_01`, названием и типом «Тестовый».
2. В «Пользователи» создаёт сотрудника и назначает ему этот автобус.
3. Передаёт заказчику адрес кабинета и учётные данные по выбранному приватному
   каналу. Отправка данных и создание публичного аккаунта автоматически не выполняются.

Если автобус ещё не создан или не назначен сотруднику, форма загрузки недоступна.
Администратор видит все автобусы, сотрудник — только назначенные.

## Сценарий заказчика

1. Войти в кабинет и открыть «Видеозаписи».
2. Выбрать автобус, код камеры и один короткий MP4. Для первого показа удобен
   эпизод на несколько минут с читаемыми экранными датой и временем, без титров
   и монтажных переходов. Поддерживается текущий ракурс и расположение часов
   камеры проекта; это не обещание работы с произвольной камерой.
3. Нажать «Загрузить видео» и дождаться завершения передачи. Если связь оборвётся,
   выбрать тот же файл, автобус и камеру — принятые части не передаются заново.
4. После загрузки файл попадает в очередь. Кабинет показывает доступность службы,
   этап чтения экранных часов, подсчёт и результат. Вкладку после передачи файла
   можно закрыть; обработка продолжается на сервере.
5. Нажать название файла. В карточке находятся результат именно этой записи,
   длительность, прогресс и причина проблемы. После завершения доступна кнопка
   «Скачать результат CSV».
6. Открыть «Отчёты», выбрать день **из экранных часов видео**, автобус и тип
   «Тестовые». Это дневной итог всех обработанных записей выбранного автобуса.
   Дата загрузки на сервер и дата записи могут отличаться.

Итог записи сохраняется вместе с контрольной точкой и не обнуляется в полночь.
Дневная статистика PostgreSQL при этом остаётся разделённой по календарным дням.
CSV карточки — итог файла, CSV раздела «Отчёты» — дневные итоги. Формат обмена с
1С пока не согласован, эти CSV предназначены для проверки.

## Что проверить на показе

- Два файла разных камер: одновременно выполняется не больше разрешённого числа
  заданий. Для одной пары автобус/камера записи идут последовательно.
- «Приостановить» во время загрузки, затем продолжить: размер не удваивается.
- Обновить страницу во время обработки: прогресс сохраняется.
- Сотрудник не видит чужие автобусы, файлы, карточки и CSV.
- MP4 без читаемых часов получает «Требуется проверка», а не выдуманную дату.
- После исправления причины администратор может повторить незавершённое задание
  без очистки результатов. Завершённые записи эта кнопка заново не считает.

Если служба недоступна, записи останутся в очереди. Неправильные карты времени
проверяет владелец по [инструкции очереди](ARCHIVE_QUEUE.md); автоматического
подтверждения спорных склеек нет. Процент загрузки относится к передаче файла,
процент обработки — к прочитанным кадрам. «Завершено» означает также доставку
последнего состояния и событий в PostgreSQL.

Показ доказывает работу загрузки, очереди, восстановления, доступа и отчётов.
Точность распознавания и приблизительное определение возраста требуют отдельной
оценки на реальных данных.
