# Полная и серверная ветки

## Назначение

`diploma` — полная версия разработки с документацией, аналитикой, тестами,
инструментами обучения и предыдущими проверяемыми весами.
`main` на этой публикации совпадает с полной версией.

`server` — самостоятельная компактная история Git, собранная из определённого
коммита полной версии. Архивные модели и отчёты не попадают даже в её историю.
В корне `release.json` фиксирует исходный коммит, профиль и SHA-256 каждого файла
поставки; сам манифест не включает свой собственный хеш.

Для сервера:

```bash
git clone --single-branch --branch server https://github.com/F3nd1uwu/bus_passenger_counter.git
cd bus_passenger_counter
python -m tools.verify_release
python -m tools.setup_env
# Настройте .env и сетевой доступ к камере по README серверной ветки.
docker compose up --build -d
```

Для диплома:

```bash
git clone --single-branch --branch diploma https://github.com/F3nd1uwu/bus_passenger_counter.git
```

## Воспроизводимая подготовка серверной версии

Из чистого зафиксированного коммита полной версии:

```bash
python -m tools.package_server --ref HEAD --output .local/server-package
python .local/server-package/tools/verify_release.py
```

Выходной путь должен отсутствовать. Сборщик читает только Git-объекты указанного
коммита; не копирует рабочую папку, `.env`, видео или состояние. Используется явный
список компонентов. Готовую папку можно проверить и скопировать в отдельный checkout
`server`, сохраняя его `.git`, либо импортировать как первый коммит новой ветки.
Не запускайте сборщик на произвольном неподготовленном коммите старой версии:
нужны актуальные код, шаблоны и метаданные.

Поставляются `main.py`, предпросмотр, `core`, `config`, `database`, три рабочие
ONNX-модели и метаданные, Docker/Compose, настройка `.env`, проверка целостности,
минимальный README, лицензии и отдельный CI. Не поставляются обучающие инструменты,
тестовые записи, тесты разработки, внешние датасеты, `reports`, большая документация,
TorchScript и экспериментальные возрастные веса.

Исходники программы в поставке совпадают с исходным коммитом. Отличаются только
предписанные шаблоны эксплуатации и Docker CMD: `main.py --profile test2`.
Включение другого профиля или замена геометрии требует повторной проверки камеры.

Не сливайте полную ветку в серверную обычным merge: это добавит исключённые файлы.
Исправления сначала вносятся в полную версию, затем серверная поставка пересобирается
и публикуется отдельным обычным коммитом без переписывания уже опубликованной истории.

## Локальная очистка

В Git не входят окружения, IDE, `__pycache__`, `.local`, приватные данные, обучающие
прогоны и рабочие базы. Воспроизводимые Python-кеши исключены из поставки;
исходные видео, ручная разметка и локальные протоколы экспериментов сохраняются.
Они не являются мусором и могут понадобиться для проверки дипломных результатов.

Реальная конфигурация `.env` не удаляется и не публикуется. Для переноса на сервер
создайте новую из шаблона и сохраните рабочие постоянные тома после первого запуска.
