# Приблизительное исключение маленьких детей

Это экспериментальная возможность, а не готовое надёжное определение возраста.
Запрошено исключать детей примерно младше семи лет, а при сомнении учитывать.
Подтверждённые возраста людей в записях неизвестны. На проверенных эпизодах
`test2.mp4` модуль пока никого не исключил; улучшение подсчёта не доказано.

## Запуск

```powershell
.\venv\Scripts\python.exe test_local.py --source data/test2.mp4 --profile test2 --child-mode model --show
```

Для короткой проверки проблемного участка:

```powershell
.\venv\Scripts\python.exe test_local.py --source data/test2.mp4 --profile test2 --child-mode model --start-frame 262000 --max-frames 1201 --show
```

Оба запуска используют предпросмотр без изменения PostgreSQL и рабочего состояния.
Обычный запуск без `--child-mode model` сохраняет прежний профиль.
Модели уже лежат в `models/candidates`, загружаются локально; кадры в интернет
не отправляются. Дополнительных пакетов для штатного запуска не требуется.

## Как принимается решение

- Детектор людей и ReID продолжают сопровождать всех людей, включая детей.
  Рост и размер бокса не используются как самостоятельный признак возраста.
- TinyCLIP сравнивает фрагмент человека с описаниями маленького ребёнка,
  взрослого и неопределённого изображения. Проверяются полный фрагмент и его центр.
  При согласии выполняется дополнительная оценка MiVOLOv2 по телу.
- Нужны три последовательных положительных результата на разных изображениях
  одного сопровождаемого человека. Сомнительный результат сбрасывает подтверждение;
  явный старший возраст блокирует исключение на этом треке.
- Результаты связаны с исходным признаком внешности. Несовпадение внешности
  превращает запоздавший результат в неопределённый. Подтверждение переносится
  только при коротком восстановлении трека, а не на все часовые совпадения ReID.
- Смешанные боксы нескольких людей, слишком мелкие и почти полнокадровые
  фрагменты не служат возрастными доказательствами.

Это несколько барьеров от ошибочного исключения взрослого. Они также существенно
снижают число распознанных детей. Сходство с текстовым описанием и предсказанное
моделью число лет не являются вероятностью возраста «младше семи».

В окне `AGE?` означает неопределённость: возрастной фильтр человека учитывает.
`CHILD` означает визуальное подтверждение по описанному правилу. Фильтр жилетки
и часовое исключение повторов продолжают действовать независимо.

Подтверждённые детские проходы сохраняются в существующем журнале событий
с `reason=CHILD`, `counted=false` и исходным направлением. Они не увеличивают
дневные IN/OUT и не запускают часовое окно учтённого прохода. Схема PostgreSQL
не менялась. Накапливаемое подтверждение и отложенные события входят в контрольную
точку; при перемотке предпросмотра возрастные результаты сбрасываются вместе с ID.

## Нагрузка и настройки

Распознавание выполняется в отдельном потоке CPU, очередь ограничена восемью
заданиями. Занятая очередь пропускает новые возрастные пробы; основной цикл
не ожидает каждую оценку. Тем не менее модели конкурируют за CPU и замедляют
обработку. В конце файла ожидание результатов ограничено пятью секундами.

Обычная траектория получает до трёх начальных проб после устойчивого обнаружения.
Если появляется положительный результат, наблюдение продолжается; если первые
пробы неопределённые, дальнейшего поиска удачного ракурса на этом треке нет.
Это ограничение нагрузки, которое также уменьшает полноту распознавания детей.

- `CHILD_MODE=disabled` — исходное поведение, значение по умолчанию.
- `CHILD_MODE=model` — включить эксперимент.
- `CHILD_MODEL_PATH=models/candidates/child_filter_v1.json` — манифест моделей.
- `CHILD_CONFIRM_SAMPLES=3` — минимум различных последовательных подтверждений;
  уменьшать ниже трёх нельзя.
- `CHILD_DECISION_DELAY_SEC=10` — задержка решения в секундах видео, чтобы дождаться
  фоновых результатов. При завершении файла решение принимается по полученным данным.

Для службы поддерживается тот же `--child-mode model` у `main.py`. Включение
меняет ключ совместимости состояния: для отдельного испытания используйте отдельную
`STATE_PATH` и отдельные тестовые идентификаторы автобуса/камеры. Не удаляйте рабочую
контрольную точку и не повторяйте архивное видео в производственные счётчики.

Сохранённые старые кэши детекций не содержат возрастных признаков: replay-инструменты
отказываются проверять по ним включённый фильтр. Для реальной проверки нужен видеопрогон:

```powershell
.\venv\Scripts\python.exe -m tools.evaluate_clip --source data/test2.mp4 --profile test2 --child-mode model --start 262000 --end 263200 --output .local/child_check/P02.json --video
```

Результаты фонового анализа находятся в `child_analysis`, исключения — в `events`.
Число `child` в статистике заданий означает положительные отдельные пробы,
а не число исключённых пассажиров. Итоговые события смотрите в JSON: кадр сохранённого
видео перед EOF может ещё показывать отложенное решение.
