# Bus Passenger Counter — серверная поставка

Считает входы и выходы по видео или камере, сохраняет события и суточные итоги
в PostgreSQL. Профиль `test2` включает детектор людей, OSNet ReID и модель
конкретной рабочей жилетки по чёрно-белому изображению.

Это версия для контролируемого полевого теста. Пропуски и смены личности остаются;
надёжное узнавание того же пассажира через час не подтверждено. Приблизительный
фильтр детей выключен, экспериментальные возрастные веса не поставляются.
Первые смены сверяйте вручную и измеряйте задержку потока.

[Полная версия и аналитика](https://github.com/F3nd1uwu/bus_passenger_counter/tree/diploma).
Исходный коммит и SHA-256 каждого файла поставки: [release.json](release.json).

## Быстрый запуск на Linux-сервере

Нужны Docker Engine с Compose и доступ сервера к камере. Один процесс обслуживает
одну дверь. GPU не требуется; производительность проверьте на своём сервере.

```bash
git clone --single-branch --branch server https://github.com/F3nd1uwu/bus_passenger_counter.git
cd bus_passenger_counter
python3 -m tools.verify_release
python3 -m tools.setup_env
```

Команда создаст приватную `.env` со случайным паролем БД, сохранив существующую.
Откройте файл и задайте `VIDEO_SOURCE`, `SOURCE_KIND`, `BUS_ID`, `CAMERA_ID`,
часовой пояс. Пароли не добавляйте в Git. Для RTSP: `SOURCE_KIND=stream`,
адрес камеры вместо заглушки `camera.example.invalid`, `VIDEO_START` пустой.
Серверу за пределами сети автобуса потребуется настроенный защищённый сетевой
доступ к источнику; программа сама не создаёт туннель.

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps -a
docker compose logs -f counter_service
```

Docker CMD уже задаёт `main.py --profile test2`. PostgreSQL не публикуется наружу.
Видео и модели монтируются только для чтения; локальное состояние — в постоянном
томе `counter_state`, PostgreSQL — в `pgdata`. Не используйте `down -v` на рабочей
установке: эта команда удаляет постоянные тома.

## Проверка видеофайла

Положите файл в `data` и измените `.env`:

```dotenv
SOURCE_KIND=file
VIDEO_SOURCE=/app/data/test2.mp4
VIDEO_START=2026-11-01T05:40:00+04:00
```

Время — пример, замените фактическим временем первого кадра. Завершённый файл
при обычном перезапуске повторно не считается. Монтажные скачки часов в изображении
не восстанавливаются автоматически; для часового правила нужна реальная временная
шкала. На новой записи используйте отдельное согласованное состояние, не стирайте
рабочую память ради обхода проверки совместимости.

## Профиль камеры и правила

Профиль в `config/profiles/test2.json` рассчитан на конкретный ракурс. Он задаёт
модели, confidence, часть геометрии, пороги и четыре потока CPU; эти значения
имеют приоритет над одноимёнными переменными `.env`. CLI имеет приоритет над
профилем. Изменение ракурса требует новой проверки зон и качества, а не только
переноса прежних параметров.

По каждому человеку действует отдельное часовое окно для IN и OUT. Первый OUT
после IN учитывается. Повтор того же направления в пределах часа сохраняется
с `counted=false`, но не увеличивает итог и не продлевает окно. Поэтому IN − OUT
не означает текущее количество людей в автобусе.

Для жилетки нужны два подтверждения. Решение может задерживаться до десяти секунд
видео, сохраняя исходное время прохода. Неопределённые модельные признаки остаются
в аудите с причиной `INSUFFICIENT_MODEL_EVIDENCE`; это нужно учитывать при сверке.
Возрастной фильтр оставляйте `CHILD_MODE=disabled`: полезность на этой камере не показана.

## Статистика

```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

```sql
SELECT traffic_date, bus_id, total_passengers AS counted_in, total_out
FROM daily_passenger_traffic ORDER BY traffic_date DESC, bus_id;

SELECT * FROM current_day_passenger_traffic
WHERE traffic_date = (CURRENT_TIMESTAMP AT TIME ZONE 'Europe/Saratov')::date;

SELECT reason, counted, COUNT(*) FROM raw_passenger_events GROUP BY reason, counted;
```

Подставьте свой часовой пояс в запрос текущего дня. История событий и контрольные
точки хранятся отдельно от дневных сумм. При временном сбое PostgreSQL после
успешного начального запуска события накапливаются в SQLite и доставляются позже.
Первому запуску без локального состояния нужна доступная БД.

## Эксплуатация и обновление

- Следите за свободным местом, доступностью камеры, свежестью кадров и ростом
  очереди. Живой процесс сам по себе не доказывает поступление изображения.
- Проверьте соответствие скорости обработки частоте камеры. Гарантии удаления
  старых кадров ради низкой задержки нет; при перегрузке возможны задержки/потери.
  На локальном CPU в плотной сцене получено около 15 FPS; это не замер сервера.
- Для остановки: `docker compose stop counter_service`, затем при необходимости
  `docker compose stop postgres`. Остановка сохраняет тома.
- Регулярно сохраняйте согласованную копию PostgreSQL, SQLite и приватной конфигурации.
  Копируйте SQLite после остановки счётчика либо через backup API; один основной
  файл работающей WAL-базы не является достаточной копией.
- Перед обновлением проверьте резервную копию и совместимость состояния. Новые
  модели, источник или пороги меняют ключ совместимости. Не удаляйте память и
  не запускайте два счётчика над одним состоянием и одной камерой.

Ветка `server` обновляется пересборкой из полной версии. Не сливайте в неё
дипломные отчёты. Новая поставка содержит новый `release.json`; проверяйте хеши
до локальной адаптации исходников/профиля. `.env` и данные в манифест не входят.

## Локальная диагностика без БД

Python 3.12 и CPU-зависимости устанавливаются командами:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --no-deps --index-url https://download.pytorch.org/whl/cpu torch==2.15.0 torchvision==0.29.2
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m tools.verify_release --smoke
.venv/bin/python test_local.py --source data/test2.mp4 --profile test2 --show
```

Для Windows используйте `.\venv\Scripts\python.exe` из существующего окружения
или создайте `.venv`. При обычном запуске Python `.env` автоматически не читается:
задавайте параметры в окружении процесса и CLI. Предпросмотр не пишет рабочую БД.
Стрелки перематывают на пять секунд, пробел включает паузу, ползунок выбирает кадр;
после перемотки тестовая память сбрасывается. Сервер без дисплея может сохранить
видео через `--output data/preview.mp4` вместо `--show`.
